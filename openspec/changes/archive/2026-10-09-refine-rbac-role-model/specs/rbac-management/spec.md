## MODIFIED Requirements

### Requirement: 管理端可調整角色的資源權限

系統 SHALL 提供管理端 API,允許調整某角色被授權的資源清單(新增/移除)。調整寫入資料庫後 MUST 使該角色的權限快取失效;該角色使用者的下一次操作 MUST 套用新權限,不要求重啟服務或重新登入。

#### Scenario: 新增權限後即時生效

- **WHEN** 「行政」角色目前不能呼叫「刪除分類」,管理員將該資源加入「行政」的權限
- **THEN** 行政角色的使用者之後呼叫「刪除分類」成功(未重啟服務、未重新登入)

#### Scenario: 移除權限後即時生效

- **WHEN** 管理員將某資源自「行政」的權限中移除
- **THEN** 行政角色的使用者之後呼叫該資源被拒(HTTP 403)

### Requirement: 管理端可調整使用者的角色

系統 SHALL 提供管理端 API,允許調整某使用者擁有的角色(指派/移除),包含將其角色清空。調整後該使用者的下一次操作 MUST 依新角色組合判斷權限。

#### Scenario: 移除角色後即時生效

- **WHEN** 管理員移除某使用者的「行政」角色
- **THEN** 該使用者之後呼叫行政專屬功能被拒(HTTP 403),即使其登入憑證仍在有效期內

#### Scenario: 清空所有角色後仍為一般使用者

- **WHEN** 管理員將某使用者的角色清單設為空
- **THEN** 該使用者之後呼叫任何受管制端點被拒(HTTP 403)
- **AND** 該使用者仍可正常使用未受管制端點(開團、下單、查詢自己的資料)

### Requirement: 管理端可查詢角色與資源清單

系統 SHALL 提供查詢 API:列出所有角色、列出所有資源、查詢某角色目前被授權的資源清單,供管理介面呈現與調整使用。

#### Scenario: 查詢角色的資源清單

- **WHEN** 管理員查詢「行政」角色的資源清單
- **THEN** 回覆該角色目前被授權的全部資源(URL pattern、HTTP method、顯示名稱)

### Requirement: 管理端 API 僅超級管理員可用

所有 RBAC 管理端 API SHALL 僅允許超級管理員角色操作;其他角色呼叫回覆 HTTP 403。

#### Scenario: 非超級管理員操作被拒

- **WHEN** 僅擁有「行政」角色的使用者呼叫調整角色權限的管理端 API
- **THEN** 系統回覆 HTTP 403,且沒有任何資料被異動
