# transaction-audit Specification

## Purpose
讓會計能查詢全體使用者的交易紀錄與儲值單,並對儲值單發起人工對單,作為對帳與處理掉單的依據。
## Requirements
### Requirement: 會計可查詢全部交易紀錄

具備對帳權限的使用者 SHALL 能查詢所有使用者的交易紀錄(含扣款與儲值),可依交易類型、使用者、建立日期區間篩選,依建立時間由新到舊分頁回覆。每筆紀錄 MUST 包含:交易編號、使用者、類型、金額(儲值為正、扣款為負)、交易後餘額、關聯訂單編號(扣款)或儲值單號(儲值)、操作者、建立時間。

#### Scenario: 依類型篩選

- **WHEN** 會計查詢類型為 RECHARGE 的交易紀錄
- **THEN** 只回覆儲值紀錄,每筆帶有儲值單號(既有種子資料的儲值紀錄為空)且金額為正

#### Scenario: 不帶篩選條件

- **WHEN** 會計不帶任何篩選條件查詢第一頁
- **THEN** 回覆所有使用者的交易紀錄第一頁與總筆數,由新到舊排列

#### Scenario: 分頁參數不合法

- **WHEN** 會計以超出上限的每頁筆數或不合法的頁碼查詢
- **THEN** 系統回覆 HTTP 400

### Requirement: 會計可查詢儲值單

具備對帳權限的使用者 SHALL 能查詢所有使用者的儲值單,可依狀態、使用者、建立日期區間篩選,依建立時間由新到舊分頁回覆。每筆 MUST 包含:儲值單號、使用者、金額、狀態、建立時間、過期時間、入帳時間。

#### Scenario: 找出已關閉的儲值單

- **WHEN** 會計查詢狀態為「已關閉」的儲值單
- **THEN** 只回覆已關閉的儲值單,可作為人工對單的對象

### Requirement: 對帳端點僅授權角色可用

查詢全部交易紀錄、查詢儲值單、人工對單 SHALL 只開放給被授權的角色;預設授權給會計(ACCOUNTANT)。其他已登入使用者呼叫 MUST 回覆 HTTP 403 且不異動任何資料。

#### Scenario: 一般使用者發起人工對單

- **WHEN** 不具對帳權限的使用者發起人工對單
- **THEN** 系統回覆 HTTP 403,儲值單與餘額不變

#### Scenario: 客服查詢全部交易紀錄

- **WHEN** 僅擁有客服角色的使用者查詢全部交易紀錄
- **THEN** 系統回覆 HTTP 403
