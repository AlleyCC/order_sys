# rbac-management Specification

## Purpose

定義角色與權限的管理端行為:管理員如何調整「角色可使用哪些資源」與「使用者擁有哪些角色」,以及調整後即時生效(不重啟、不重新登入)的保證。

## Requirements

### Requirement: 管理端可調整角色的資源權限

系統 SHALL 提供管理端 API,允許調整某角色被授權的資源清單(新增/移除)。調整寫入資料庫後 MUST 使該角色的權限快取失效;該角色使用者的下一次操作 MUST 套用新權限,不要求重啟服務或重新登入。

#### Scenario: 新增權限後即時生效

- **WHEN** 「團長」角色目前不能呼叫「刪除團購活動」,管理員將該資源加入「團長」的權限
- **THEN** 團長角色的使用者之後呼叫「刪除團購活動」成功(未重啟服務、未重新登入)

#### Scenario: 移除權限後即時生效

- **WHEN** 管理員將某資源自「團長」的權限中移除
- **THEN** 團長角色的使用者之後呼叫該資源被拒(HTTP 403)

### Requirement: 管理端可調整使用者的角色

系統 SHALL 提供管理端 API,允許調整某使用者擁有的角色(指派/移除)。調整後該使用者的下一次操作 MUST 依新角色組合判斷權限。

#### Scenario: 移除角色後即時生效

- **WHEN** 管理員移除某使用者的「團長」角色
- **THEN** 該使用者之後呼叫團長專屬功能被拒(HTTP 403),即使其登入憑證仍在有效期內

### Requirement: 管理端可查詢角色與資源清單

系統 SHALL 提供查詢 API:列出所有角色、列出所有資源、查詢某角色目前被授權的資源清單,供管理介面呈現與調整使用。

#### Scenario: 查詢角色的資源清單

- **WHEN** 管理員查詢「團長」角色的資源清單
- **THEN** 回覆該角色目前被授權的全部資源(URL pattern、HTTP method、顯示名稱)

### Requirement: 管理端 API 僅超級管理員可用

所有 RBAC 管理端 API SHALL 僅允許超級管理員角色操作;其他角色呼叫回覆 HTTP 403。

#### Scenario: 非超級管理員操作被拒

- **WHEN** 僅擁有「團長」角色的使用者呼叫調整角色權限的管理端 API
- **THEN** 系統回覆 HTTP 403,且沒有任何資料被異動

### Requirement: 超級管理員恆具全部權限

超級管理員角色 SHALL 恆常通過所有受保護端點的授權判斷,不依賴資源表逐筆授權;此為系統不變量,不可經由管理端調整移除。

#### Scenario: 超級管理員呼叫任意受保護端點

- **WHEN** 擁有超級管理員角色的使用者呼叫任一受保護端點
- **THEN** 授權判斷放行(業務層的資料檢核不在此限)
